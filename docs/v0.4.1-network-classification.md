# PatSecure v0.4.1 — classification réseau

Document de travail pour la prochaine version de PatSecure.

## Objectif

Réduire les faux positifs dans l'audit des sockets réseau sans masquer les véritables services à vérifier.

PatSecure ne doit jamais conclure qu'un port est « exposé sur Internet » à partir de `ss` seul. Une écoute locale ou multi-interface indique seulement la portée de la socket sur la machine. L'exposition Internet dépend aussi du pare-feu, du routage/NAT, des redirections de ports et, en IPv6, du filtrage entrant.

## Règles v0.4.1

| Cas | Niveau | Interprétation |
|---|---|---|
| `127.0.0.1` / `::1` | `OK` | boucle locale uniquement |
| UDP éphémère + processus identifié | `INFO` | socket client probable, pas assimilée à un serveur permanent |
| Avahi UDP 5353 | `INFO` | découverte mDNS locale connue |
| NetworkManager UDP 546 | `INFO` | DHCPv6 connu |
| UDP d'un client connu (`firefox-bin`, navigateur, `systemd-timesyncd`, etc.) | `INFO` | programme client identifié |
| TCP `LISTEN` hors boucle locale | `ATTENTION` | service joignable depuis au moins une interface ; à vérifier |
| UDP non éphémère non classé | `ATTENTION` | service permanent possible |
| socket hors boucle locale sans processus identifié | `ATTENTION` | attribution impossible ; investigation nécessaire |

## Ports UDP éphémères

La plage n'est pas codée en dur : PatSecure lit `/proc/sys/net/ipv4/ip_local_port_range`. Un repli `32768-60999` est prévu uniquement si cette information n'est pas disponible.

Cela évite une règle fragile du type « port élevé = forcément sûr ».

## Confidentialité

Le moteur reçoit l'adresse locale pour déterminer la portée (`loopback`, `interface`, `all-interfaces`) mais ne la renvoie pas dans sa sortie de classification.

Le rapport partageable pourra donc afficher :

- protocole ;
- port ;
- nom du processus ;
- niveau (`OK`, `INFO`, `ATTENTION`) ;
- motif de classification ;

sans publier d'adresse IP locale, d'adresse MAC, de nom de machine ou de nom d'utilisateur.

## Intégration prévue dans `patsecure.sh`

1. Collecter les sockets avec `ss` comme en v0.4.0.
2. Extraire protocole, état, adresse locale et processus.
3. Passer chaque entrée au moteur de classification.
4. Afficher un résumé lisible et conserver la sortie brute de `ss` uniquement dans le rapport privé.
5. Conserver séparément l'analyse UFW/nftables et IPv6.
6. Ne jamais transformer une écoute `0.0.0.0` / `[::]` en affirmation « exposé sur Internet ».

## Validation avant fusion

Le fichier `tests/test-network-classifier-v0.4.1.sh` couvre les cas principaux. La branche doit ensuite être testée sur Deepin avec les sockets réelles de la machine avant toute fusion dans `main`.
